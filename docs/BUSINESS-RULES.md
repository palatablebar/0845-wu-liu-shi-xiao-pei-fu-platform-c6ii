# 业务规则

## 使用者

干线客服专员使用本工作台处理工作日顺延与赔付阶梯。

## 主规则

截止时点落在非工作日时顺延，计算延误时扣除暂停时长与非工作时段，再套赔付档。

计算以整数最小单位或十进制定点数为准，避免二进制浮点在边界上漂移。无法完成前置校验的行进入隔离区；跨行规则在计算后标记阻断或人工复核。

## 判定

- `PASS`：业务结果在允许范围内。
- `REVIEW`：数据可计算，但需要人工确认或存在轻微偏离。
- `REJECT`：存在来源、守恒、方向或上限阻断，不能签发。

## 暂停凭据

暂停凭据按运单号覆盖声明的暂停时长，可分批补录，可能在批次计算完成之后才到。

- 凭据归一为 `{运单号: 小时数}`，并生成稳定的凭据摘要；顺序不同不改变摘要。
- 有效凭据覆盖该行的 `paused_hours`；未被覆盖的行沿用声明值。
- 非数字、负数或同一运单冲突的凭据成为**无效暂停行**，该行不参与计算，原因码保留在异常列表。

## 批次与版本

批次身份只由来源字节与规则决定，**不包含凭据**：

- 同一来源重复执行、重复提交，只沿用原批次，不新增一笔赔付；
- 暂停凭据补齐使来源摘要变化时：
  - 未签发（`DRAFT`/`HELD`）批次**原地重算**，计算代次 `generation` 递增，批次号不变；
  - 已签发（`APPROVED`）批次**停止改写**，保留原金额、原来源摘要与原计算版本；
- 来源摘要 = 基础来源字节 + 规则 + 有效暂停凭据；计算版本 = 计算结果的结构化摘要。

## 守恒

来源行必须被下列互斥桶完整划分，且和等于来源行：

```
来源行 = 精确重复 + 忽略 + 采信层隔离 + 无效暂停行 + 其他整理隔离 + 入账行
采信行 = 入账行 + 无效暂停行 + 其他整理隔离
```

任一守恒不成立即视为对账失败，**不得签发**。

## 签发

签发要求同时满足：

- 阻断项（`REJECT`）为零；
- 全部守恒检查通过；
- 批次携带来源摘要与计算版本。

签发时冻结当时的金额、来源摘要与计算版本，并递增复核版本号；陈旧版本提交会被拒绝。证据只在签发后生成，且只从冻结版本读取，重复下载得到同一份。
